# MAX Userbot — автоматизация пользовательских аккаунтов в мессенджере МАКС (max.ru)

Юзербот для мессенджера MAX: платформа автоматизации действий от имени обычного
пользовательского аккаунта — мультиаккаунт, пересылка сообщений, планировщик,
плагины.

> **Статус: ранняя разработка.** Работает каркас — демон, локальный API и CLI —
> но пока на заглушечном транспорте: подключения к настоящему MAX ещё нет.
> Ландшафт ниши — в [docs/research.md](docs/research.md), архитектура — в
> [docs/stack.md](docs/stack.md), текущие задачи — в [TASKS.md](TASKS.md).

## Чем юзербот отличается от бота в MAX

| | Бот (Bot API) | Юзербот (этот проект) |
|---|---|---|
| От чьего имени работает | отдельный аккаунт-бот | ваш обычный аккаунт |
| API | официальный `platform-api.max.ru` | внутренний API мессенджера |
| Кто может опубликовать | только верифицированные юрлица, ИП и самозанятые — резиденты РФ | ограничений на публикацию нет |
| Видит переписку в обычных чатах | нет | да |
| Поддержка со стороны MAX | официальная | отсутствует |

Коротко: бот — это отдельный участник чата, которого нужно куда-то пригласить.
Юзербот работает как вы сами и видит ровно то, что видите вы.

## Что уже работает

- **Два способа входа** — по номеру телефона с кодом и по QR-коду, который
  сканируется приложением MAX. QR рисуется прямо в терминале.
- **Веб-панель** — добавление и авторизация аккаунтов мышью, без командной
  строки: список аккаунтов с состояниями, вход по коду и по QR.
- **Демон** с пулом аккаунтов и очередью отправки: дедупликация по ключу
  идемпотентности, ограничение частоты, отложенные повторы, явные состояния
  аккаунта.
- **Восстановление после сбоя** — добор пропущенных событий по курсору,
  переподключение с нарастающей паузой, сверка отправки, исход которой остался
  неизвестным.
- **Шифрование сессий** — в базе они лежат зашифрованными, ключ хранится вне
  базы.
- **Локальный API** — HTTP и WebSocket, только на петлевом интерфейсе, с
  обязательным токеном.
- **Два CLI** — `maxub` для человека и `maxubctl` для скриптов и агентов.
- **Docker** — сборка, запуск и тесты.

Транспорт пока заглушечный (`stub`): весь путь проверяется без реального
аккаунта MAX. Подключение `PyMax` — после spike-теста, см. [TASKS.md](TASKS.md).

## Что планируется

- **Пересылка (форвардинг)** — правила «из чата А в чат Б» с фильтрами и
  преобразованием текста, живая синхронизация.
- **Планировщик** — отложенные и повторяющиеся отправки.
- **Плагины** — модульное ядро, свои сценарии без правки самого ядра.

## Быстрый старт

```bash
docker compose up -d --build
docker compose exec userbot maxub accounts list
```

Порт наружу не публикуется: API даёт полный контроль над аккаунтами, поэтому
доступ к нему — только внутри контейнера.

Полный путь от добавления аккаунта до отправки сообщения:

```bash
docker compose exec userbot maxub accounts add --phone "+79990000000" --label рабочий
docker compose exec userbot maxub login start --account-id 1
docker compose exec userbot maxub login complete --challenge-id <id> --code <код>
docker compose exec userbot maxub send --account-id 1 --chat-id <чат> --text "привет"
docker compose exec userbot maxub history --account-id 1 --chat-id <чат>
```

У заглушечного транспорта код подтверждения всегда `00000`.

## Вход по QR-коду

Второй способ авторизации: код сканируется приложением MAX на телефоне, SMS не
нужен. Одна команда показывает код и ждёт подтверждения:

```bash
docker compose exec userbot maxub login qr --account-id 1
```

QR рисуется символами, поэтому работает и по ssh, и в выводе
`docker compose exec` — картинка не требуется.

Для скриптов те же шаги разделены на два неблокирующих вызова:

```bash
docker compose exec userbot maxubctl login qr-start --account-id 1
docker compose exec userbot maxubctl login qr-poll --challenge-id <id>
```

`qr-poll` возвращает `pending`, `confirmed` или `expired` и не ждёт.

## Веб-панель

Если возиться с командами не хочется, аккаунты добавляются и авторизуются через
страницу. Она показывает список аккаунтов с их состоянием и последней ошибкой,
умеет запросить код на телефон, показать QR для сканирования и отключить
аккаунт.

Панель отдаёт тот же демон, отдельный сервер поднимать не нужно. По умолчанию
порт наружу не публикуется — как открыть доступ, написано в комментарии внутри
[docker-compose.yml](docker-compose.yml). После этого:

1. Откройте `http://127.0.0.1:8765/web`.
2. Введите токен демона — его выдаст
   `docker compose exec userbot cat /data/api_token`.

Токен вводится один раз и в браузере не хранится: он обменивается на сессионную
cookie (`HttpOnly`, `SameSite=Strict`, 12 часов), а каждый изменяющий запрос
дополнительно подписывается CSRF-меткой, которая живёт только в памяти вкладки.
Страница не тянет ни одного внешнего файла и работает без интернета. Панель
управляет только аккаунтами: отправки сообщений и просмотра истории в ней нет,
это осталось в CLI.

Панель отключается целиком, если она не нужна:

```bash
MAXUB_WEB_UI=false
```

Что умеет транспорт конкретного аккаунта, можно спросить явно — гадать не нужно:

```bash
docker compose exec userbot maxubctl capabilities --account-id 1
```

## `maxubctl` — режим для скриптов и агентов

`maxubctl` — та же программа, что и `maxub`, но заточенная под неинтерактивный
вызов: JSON по умолчанию, никаких запросов ввода, токен подхватывается из
каталога данных. Агент заходит в работающий контейнер и действует сам:

```bash
docker compose exec userbot maxubctl status
docker compose exec userbot maxubctl events --after-id 12
```

Коды выхода стабильны — разбирать текст ошибки не нужно:

| Код | Значение |
|---|---|
| 0 | успех |
| 1 | прочая ошибка |
| 2 | ошибка аргументов |
| 3 | демон недоступен |
| 4 | неверный или отсутствующий токен |
| 5 | конфликт состояния (дубль аккаунта, аккаунт не готов) |
| 6 | возможность не поддерживается транспортом |
| 7 | объект не найден |

Курсор `--after-id` в `events` позволяет читать поток без повторов — агент
хранит последний увиденный `id` и продолжает с него.

## Хранение секретов

В каталоге данных лежат две чувствительные вещи: токен доступа к API и база с
сессиями аккаунтов. Права — `0700` на каталог и `0600` на файлы.

Сессии в базе зашифрованы. Ключ берётся из переменной `MAXUB_SECRET_KEY`, а если
её нет — создаётся файл `secret.key` рядом с базой. Переменная предпочтительнее:
она позволяет держать ключ отдельно от тома с данными, и тогда копия базы без
ключа бесполезна.

Каталог `data/` внесён в `.gitignore` — секреты не должны попадать в
репозиторий.

## Разработка

```bash
docker build -t max-userbot:dev .
docker run --rm -v "$PWD:/app" -w /app --user "$(id -u):$(id -g)" \
    -e HOME=/tmp -e PYTHONPATH=/app/src max-userbot:dev \
    sh -c "python -m pytest -q && ruff check . && mypy src/maxub"
```

`PYTHONPATH=/app/src` обязателен: иначе Python возьмёт копию пакета, вшитую в
образ, а не примонтированный исходник.

## FAQ

**Что такое юзербот для MAX?**
Программа, которая подключается к мессенджеру MAX под вашим обычным аккаунтом и
выполняет действия за вас: отвечает, пересылает, собирает сообщения, работает по
расписанию.

**Чем юзербот отличается от чат-бота MAX?**
Бот требует верификации юрлица и работает как отдельный участник чата. Юзербот
действует от вашего имени и не требует регистрации в MAX. Подробности — в
таблице выше.

**Можно ли вести несколько аккаунтов MAX одновременно?**
Да, мультиаккаунт — одна из ключевых задач проекта.

**Как получить сессию MAX?**
Через авторизацию по номеру телефона, как в обычном клиенте. Сессия сохраняется
локально и переиспользуется при следующих запусках.

**Нужен ли для юзербота официальный MAX Bot API?**
Нет. Bot API покрывает только ботов и не даёт доступа к пользовательскому
аккаунту.

**Существуют ли готовые библиотеки для MAX?**
Да, несколько низкоуровневых обёрток внутреннего API — их обзор в
[docs/research.md](docs/research.md).

## Дисклеймер

Проект не является официальным продуктом MAX и не связан с VK. Он опирается на
внутренний (не документированный) API мессенджера, полученный методом обратной
разработки. Из этого следует:

- Использование юзербота **противоречит пользовательскому соглашению MAX**.
  Аккаунт может быть заблокирован.
- Внутренний API меняется без предупреждения — работоспособность не
  гарантируется.
- Массовые действия (рассылки, добавление в чаты, сбор данных) с пользовательских
  аккаунтов — прямой путь к блокировке и, в зависимости от сценария, к нарушению
  законодательства о персональных данных.

Используйте на свой страх и риск, для личной автоматизации собственных аккаунтов.

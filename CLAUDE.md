# CLAUDE.md

Инструкции для работы над проектом. Действуют поверх глобальных правил в
`~/.claude/CLAUDE.md`.

## Что это за проект

`max-messenger-userbot` — платформа автоматизации пользовательских аккаунтов
мессенджера MAX (max.ru). Не бот: работает от имени обычного аккаунта через
внутренний (не документированный) API мессенджера.

Ниша выбрана осознанно: под MAX существует шесть библиотек транспортного уровня
и ни одной платформы поверх них. Ориентир по продукту — «Ultroid для MAX».
Детали и цифры рынка — в [docs/research.md](docs/research.md).

Направление зависимостей одностороннее: `api` и `cli` знают про `core`,
`core` знает про `transport` только через Protocol. Обратных импортов нет —
ядро не должно зависеть ни от FastAPI, ни от Typer, ни от моделей конкретной
транспортной библиотеки.

Разделение источников правды: изменения — в CHANGELOG, статус работ — в TASKS,
рынок — в research, продвижение — в seo. Один факт живёт в одном файле.

## Архитектурные принципы

1. **Транспорт изолирован за интерфейсом.** Внутренний API MAX меняется без
   предупреждения (за последний год сменились домен и схема авторизации).
   Конкретная обёртка (`PyMax`, `pyromax`) — деталь реализации за абстракцией,
   а не основа кода. Смена протокола не должна переписывать платформу.
2. **Лимиты по умолчанию, а не опцией.** Консервативные задержки между
   действиями и адаптивный backoff включены изначально. Массовые рассылки не
   входят в состав функциональности.
3. **Сессии — секреты.** Файлы сессий и токены никогда не попадают в git, права
   `0600`, отдельный каталог, не смешивается с конфигом.
4. **Мультиаккаунт с первого дня.** Один процесс — пул аккаунтов с изолированным
   состоянием. Дописать это позже дороже, чем заложить сразу.
5. **Плагины поверх ядра.** Пользовательские сценарии не требуют правки ядра.
6. **Модульность.** Файлы больше ~200 строк разбиваются на логические части.

## Окружение

- Запуск, сборка и тесты — только в Docker, ничего не ставить локально.
- Docker выполняется от пользователя `deploy2`, без `sudo`. Если контейнер пишет
  в смонтированные каталоги, в сервисе указывается `user: "<UID>:<GID>"` этого
  пользователя.
- Доступ к репозиторию — по SSH-алиасу `github-max` (настроен в
  `~/.ssh/config`, deploy key `~/.ssh/id_ed25519`).

## Перед реализацией

Согласно глобальным правилам, план и результат прогоняются через Codex и
Antigravity параллельно (`ask-codex`, `ask-agy`). Для этого проекта это особенно
касается: выбора базовой библиотеки транспорта, схемы хранения сессий и любых
изменений, связанных с лимитами и антибан-логикой.

## Правовой контекст

Проект противоречит пользовательскому соглашению MAX и опирается на обратную
разработку. Позиционирование — личная автоматизация собственных аккаунтов.
Функции массовых рассылок, сбора чужих данных и добавления пользователей в чаты
в проект не добавляются. Дисклеймер в README — обязательная часть, не удалять.

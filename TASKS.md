## Ближайшие шаги

Порядок v1 задан ревью Codex — сначала надёжный жизненный цикл аккаунта и
сообщений, всё остальное поверх доказанного ядра.

1. **Каркас репозитория** — pyproject, Docker, линтеры, структура пакета.
2. **Транспортный адаптер** — интерфейс с `capabilities` и заглушечная
   реализация для тестов.
3. **Ядро** — модель данных с `account_id` с самого начала, состояния аккаунта,
   token-bucket с jitter, персистентная очередь с дедупликацией.
4. **Локальный API** — `health/status`, `login`, `accounts`, `send`, `events`,
   `shutdown`; WebSocket только для событий.
5. **`maxubctl`** — тонкий клиент API с машиночитаемым выводом для агентов.
6. **Spike по транспорту** — `PyMax` против `pyromax`: авторизация, reconnect,
   пагинация истории, медиа, edit/delete, пропуски событий, два аккаунта.
   Только после этого — реальный транспорт.
7. **Шифрование сессий** — ключ вне SQLite, атомарная ротация.
8. **Определить лицензию проекта** — до публикации пакета.
9. **Заполнить настройки GitHub** — description и topics по
   [docs/seo.md](docs/seo.md). Делается вручную в веб-интерфейсе.
10. **Забронировать `max-userbot` на PyPI** — свободно на 2026-07-29.

Отложено за пределы v1: планировщик, плагины через `entry_points`, SPA, второй
транспортный адаптер, мост в Telegram (первый внешний плагин после стабилизации
ядра).

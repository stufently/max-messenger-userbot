# Исследование ниши: автоматизация MAX

Данные собраны 2026-07-29 (GitHub Search API, звёзды и даты последнего пуша — на
эту дату). Файл — источник правды по рынку и обоснованию позиционирования.
Статус работ здесь не ведётся, он в [../TASKS.md](../TASKS.md).

## 1. Официальная платформа MAX

- Документация для разработчиков: `dev.max.ru`.
- Bot API живёт на домене `platform-api.max.ru`; старый `botapi.max.ru` отключён
  с 1 октября. Токен передаётся заголовком `Authorization`, передача через
  query-параметры не поддерживается.
- Метод `GET /chats` не поддерживается начиная с июня 2026.
- Публиковать ботов и мини-приложения могут только верифицированные юрлица, ИП и
  самозанятые — резиденты РФ.
- Официальные библиотеки: `max-messenger/max-botapi-python`,
  `max-messenger/max-bot-api-client-ts`, `max-messenger/max-bot-api-client-go`.

Всё это относится к **ботам** и не покрывает пользовательские аккаунты — отсюда
существование отдельной юзербот-ветки, построенной на реверс-инжиниринге.

## 3. Что взято и что отвергнуто у аналогов

Сверка с Ultroid, Hikka/Heroku, Userge, PagerMaid, Telethon, Pyrogram, мостами
mautrix и лимитерами Synapse (2026-07-29).

**Взято:**

- порог, выше которого ожидание лимита не высиживается на месте (у Telethon
  `flood_sleep_threshold = 60`, у Pyrogram `SLEEP_THRESHOLD = 10`);
- запасной штраф, когда сервер отказал по лимиту, но срока не назвал;
- ориентир по частоте: наши 12 сообщений в минуту — это `rc_message` Synapse
  (0.2/с), при более строгом всплеске (3 против 10).

**Отвергнуто осознанно:**

- **Подмена отпечатка клиента** — случайные имя приложения и версия ОС, как в
  Heroku. Это уже не «работать своим аккаунтом», а прятаться от оператора
  сервиса. Позиционирование проекта — личная автоматизация, а не обход
  детектирования; такие функции не добавляются по той же причине, по какой не
  добавляются рассылки.
- **Автоустановка зависимостей плагина** (`pip`/`apt` из кода, у Heroku — с
  добавлением `sudo`) и **клонирование git по адресу из БД** (Ultroid) — прямые
  пути к выполнению чужого кода.
- **Эндпоинты выполнения кода** — `.eval`, `.terminal`, `run_sh`, `run_eval`.
- **Телеметрия по умолчанию.** У PagerMaid трейсбек уходит вместе с текстом
  сообщения пользователя на зашитый в код идентификатор.
- **Хранение состояния в служебном чате мессенджера** (Hikka): привязывает
  данные к живому аккаунту и расширяет поверхность утечки.
- **Массовые рассылки** — есть штатно у Ultroid, у нас за периметром.

**Чужие грабли, которые стоит помнить:**

- у Hikka веб-панель дала [CVE-2025-52572](https://app.opencve.io/cve/CVE-2025-52572)
  с оценкой 10.0 и эксплуатацией в дикой природе — отсюда наши требования к
  панели: обязательный токен без ветки «если не задан, пускаем», проверка
  `Host`, одноразовый код входа вместо буфера обмена;
- у Ultroid заявленная в README защита от опасных плагинов не существовала
  четыре с половиной года: класс вызывался, но не был определён, импорт всегда
  падал. Никто не заметил, потому что не было теста на срабатывание защиты;
- мультиаккаунт, дописанный поверх готовой платформы, у Ultroid остался
  сломанным — подтверждение принципа «закладывать сразу».

## 5. Риски, влияющие на архитектуру

1. **Внутренний API нестабилен.** За последний год MAX сменил домен Bot API и
   схему авторизации; внутренний API меняется чаще и без анонсов.
   → Транспорт изолируется за интерфейсом, чтобы смена протокола не переписывала
   платформу целиком.
2. **Блокировки аккаунтов — задокументированы, а не предположены.**
   - 01.10.2025 пресс-служба MAX подтвердила блокировку доступа через сторонние
     клиенты (reMAX, Komet, «Зелёный Макс», WhiteMAX); блокировали по номеру
     телефона. Источники: [РИА](https://ria.ru/20251001/max-2045613110.html),
     [Новая газета](https://novayagazeta.ru/articles/2025/10/01/max-nachal-blokirovat-polzovatelei-kotorye-s-pomoshchiu-modov-pytaiutsia-oboiti-ego-sbor-personalnykh-dannykh-v-servise-eto-obiasnili-popytkoi-ogradit-rossiian-ot-moshennikov-news),
     [Хабр](https://habr.com/ru/news/952426/).
   - Известны бессрочные блокировки за **однотипный текст**, разосланный вручную
     разным людям. Детектор смотрит не только на частоту.
   - Численных серверных лимитов для пользовательских действий MAX не публикует;
     «30 rps» из вторичных источников относится к Bot API, а не к клиенту.
   → Консервативные лимиты и адаптивные задержки по умолчанию, а не опцией.
   → Любой будущий автоответчик обязан **разнообразить формулировки**: одинаковый
   текст ловится фильтром даже при законном сценарии.
   → Отсюда же ставка на локальный запуск (Windows-дистрибутив): реверс
   Android-клиента показал сбор сетевого отпечатка, включая флаг активности VPN.
3. **Нарушение ToS — сразу по нескольким независимым пунктам.** В редакции
   [legal.max.ru/ps](https://legal.max.ru/ps): 4.3.7 (автоматизированные скрипты
   для взаимодействия с Сервисом, обратная разработка), 4.3.10 (использование
   иначе как через интерфейс Компании), 4.4 (интеграция со сторонним ПО без
   отдельного соглашения); отдельно 4.3.4 (спам) и 4.3.13 (массовые однотипные
   действия). Плюс рамка 156-ФЗ от 24.06.2025: MAX юридически элемент
   госинфраструктуры, и это упомянуто в самом соглашении.
   → Явный дисклеймер в README, позиционирование как личная автоматизация
   собственных аккаунтов, без функций массовых рассылок «из коробки».
4. **Зависимость от чужого реверса.** Библиотеки-обёртки могут быть заброшены
   (`max-user-api` — последний пуш январь 2026).
   → Не привязываться жёстко к одной обёртке; активные кандидаты — `PyMax` и
   `pyromax`.

# Нейминг и SEO-чеклист

Целевая аудитория — русскоязычная. Оптимизируем под Яндекс и Google.ru.
Обоснование выбора ниши — в [research.md](research.md).

## Принятые имена

| Что | Значение | Статус на 2026-07-29 |
|---|---|---|
| Репозиторий | `max-messenger-userbot` | занят нами |
| PyPI-пакет | `max-userbot` | свободен, забрать до релиза |
| CLI-команда | `maxub` | — |
| Запасной бренд | `maxroid` | свободен на GitHub и PyPI |

Почему не `max-userbot` для имени репозитория: точное совпадение уже есть у трёх
чужих репозиториев (`lxxxjinxxxl-glitch/max-userbot`, `Hshdhr1/Max-Userbot`,
`powdergotpower/Max-userbot`) — это Telegram-юзерботы, названные по имени
человека «Max». Конкурировать с ними за собственное имя не нужно. На PyPI такой
конкуренции нет, поэтому там слаг короче.

Почему не короткий бренд с самого начала: слово «max» — омоним, тонет в выдаче
(`maxflow` — 574 репозитория, `automax` — 367, `max-automation` — 391). Имя
обязано содержать дизамбигуатор `messenger`. Бренд без аудитории ранжируется
только по себе самому, поэтому `maxroid` держим в резерве.

## Что заполнить в настройках GitHub

**Description** (идёт в сниппет поисковика, держать в ~130 символах):

```
Юзербот для мессенджера MAX (Макс, max.ru): автоматизация пользовательских аккаунтов, мультиаккаунт, пересылка, планировщик
```

**Topics** — каждая тема это отдельная индексируемая страница
`github.com/topics/<тема>`; `max-userbot` и `maxapi` почти пусты (2 и 3
репозитория), туда попадаем в топ сразу:

```
max-userbot, max-messenger, max-user-api, userbot, maxapi,
automation, python, asyncio, multiaccount, max-ru
```

**Website** — заполнить, когда появится сайт документации.

## Правила для текстов

- H1 в README дословно повторяет поисковый запрос, а не бренд:
  `MAX Userbot — автоматизация пользовательских аккаунтов в мессенджере МАКС (max.ru)`.
- В тексте обязательно присутствуют все написания: `MAX`, `Макс`, `max.ru`,
  `юзербот`. Яндекс работает по кириллическим формам, имя репозитория их не
  содержит.
- Раздел FAQ в README формулируется вопросами в виде реальных запросов
  («Чем юзербот отличается от бота в MAX?», «Как получить сессию MAX?»,
  «Можно ли вести несколько аккаунтов MAX?»). Длинный хвост даёт больше трафика,
  чем ключевик в имени репозитория.
- README — только на русском (решение по аудитории от 2026-07-29).

## Правила под ИИ-поиск (GEO)

Всё больше запросов заканчивается не переходом по ссылке, а ответом Алисы,
ChatGPT, Perplexity или обзора в выдаче. Такой ответ собирается из фрагментов
текста, поэтому оптимизируется не страница целиком, а отдельный абзац: он должен
быть понятен, будучи вырванным из контекста.

- **Ответ первой строкой.** Первый абзац README — определение вида «MAX Userbot
  — это …», а не приветствие. Модель цитирует начало.
- **Абзац самодостаточен.** Никаких «как сказано выше» и «этот проект» без имени.
  Фрагмент обязан читаться отдельно, поэтому имя сущности повторяется.
- **Заголовки — вопросами.** «Чем юзербот отличается от бота в MAX» находится и
  цитируется, «Возможности» — нет.
- **Таблицы вместо перечислений через запятую.** Сравнительная таблица —
  наиболее охотно извлекаемый формат: у каждой строки готовая пара «признак —
  значение».
- **Конкретика с датой.** «Шесть библиотек на 29 июля 2026» весит больше, чем
  «несколько библиотек»: проверяемое утверждение цитируют, расплывчатое — нет.
  Дата обязательна, иначе цифра со временем превращается во враньё.
- **Честный статус.** Заглушечный транспорт назван прямо. Модель, поймавшая
  расхождение между обещанием и кодом, перестаёт цитировать источник целиком.
- **Синонимы и написания собраны в одном разделе** («Термины и синонимы»): MAX,
  Макс, max.ru, юзербот, userbot, внутренний API. Так запрос на любой форме
  сходится с текстом.
- **FAQ отвечает первым предложением**, а не подводит к ответу. Вопросы берутся
  из реальных формулировок: «забанят ли аккаунт», «можно ли без Python».

Чего не делать: списков ключевых слов, повторов ради плотности, обещаний
функций, которых нет. Первое игнорируется, третье выясняется мгновенно — код
открыт.

## Приоритеты по силе влияния

1. Имя репозитория (входит в URL) — зафиксировано.
2. Description — заполнить в настройках.
3. H1 и первый абзац README — сделано.
4. Topics — заполнить в настройках.
5. Звёзды и свежесть коммитов — следствие работы над проектом.
6. Отдельный сайт документации (GitHub Pages) — Яндекс ранжирует docs-сайты
   выше, чем страницы репозиториев. К релизу.
